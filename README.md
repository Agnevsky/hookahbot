# Hookah Bar Order Bot

Telegram-бот для учёта заказов кальянной — табак, бар, прочее, и
веб-приложение (Telegram Mini App) к нему: просмотр списка, добавление,
редактирование и удаление отдельных позиций, управление марками табака.

## Структура проекта

```
hookahbot/
├── bot.py               — точка входа: бот + веб-сервер в одном процессе
├── config.py            — настройки через pydantic-settings
├── notify.py            — оповещения и рассылки (общие для бота и приложения)
├── Caddyfile            — HTTPS-прокси для веб-приложения
├── .env                 — токены и пароли (в git не коммитится!)
├── .env.example         — шаблон .env
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
│
├── db/
│   ├── models.py        — SQLAlchemy модели + Pydantic схемы
│   ├── session.py       — async engine и фабрика сессий
│   ├── queries.py       — все запросы к БД
│   └── fill.py          — заполненность: пулы, ёмкости, пороги
│
└── tg/
    ├── keyboards.py     — все клавиатуры и callback_data
    ├── handlers.py      — хендлеры диалога
    ├── formatters.py    — форматирование списков (HTML)
    └── router.py        — регистрация хендлеров
│
└── webapp/
    ├── api.py           — HTTP-API приложения (FastAPI)
    ├── auth.py          — проверка подписи Telegram (initData)
    └── static/          — фронтенд: index.html, app.js, style.css
```

## Запуск на сервере (Docker)

На сервере нужен только Docker с плагином compose. Отдельно ставить
PostgreSQL и создавать базу вручную **не нужно**: база поднимается
контейнером и создаётся из `POSTGRES_DB`, а таблицы бот создаёт сам
при первом старте.

```bash
git clone <репозиторий> hookahbot
cd hookahbot

cp .env.example .env
nano .env          # BOT_TOKEN, пароль БД, ADMIN_IDS, RESPONSIBLE, домен

docker compose --profile https up -d --build   # с HTTPS для веб-приложения
# или без веб-приложения / со своим nginx:
# docker compose up -d --build
docker compose logs -f bot
```

Обновление после пуша новых коммитов:

```bash
git pull
docker compose --profile https up -d --build
```

### Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Создание БД в контейнере postgres |
| `DATABASE_URL` | Строка подключения бота. Хост — `postgres` (имя сервиса), **не** `localhost` |
| `PERSISTENCE_PATH` | Необязательно. Файл состояния диалогов, по умолчанию `data/bot_state.pickle` |
| `CAPACITY_TOBACCO` / `CAPACITY_BAR_DRINKS` / `CAPACITY_OTHER` | Необязательно. Ёмкость пулов, по умолчанию 50 / 15 / 15 |
| `FILL_THRESHOLDS` | Необязательно. Пороги оповещений в процентах, JSON-список, по умолчанию `[50,80,100]` |
| `ADMIN_IDS` | Кто видит кнопки «📤 Отправить …» и управляет марками табака. JSON-список Telegram ID, например `[111111111]` |
| `RESPONSIBLE` | Ответственные за категории, JSON: `[{"name":"Юре","telegram_id":222222222,"categories":["tobacco"]}]`. `name` — в дательном падеже для кнопки, категории — `tobacco`, `bar`, `other` |
| `WEBAPP_URL` | Публичный HTTPS-адрес веб-приложения, например `https://hookah.example.com/`. Пусто — кнопки приложения в боте нет |
| `WEBAPP_DOMAIN` | Домен для Caddy (`--profile https`): он сам получит сертификат Let's Encrypt |
| `WEBAPP_PORT` | Необязательно. Порт веб-сервера, по умолчанию `8080` (наружу — только на `127.0.0.1`) |
| `WEBAPP_AUTH_TTL` | Необязательно. Сколько секунд действует вход в приложение, по умолчанию сутки |

Telegram ID людей хранятся только в `.env`, в коде их нет. Свой ID можно
узнать у [@userinfobot](https://t.me/userinfobot).

Пример:
```env
DATABASE_URL=postgresql+asyncpg://hookah:change_me@postgres:5432/hookah_bot
```

### Данные

Два именованных тома переживают пересборку контейнеров:

- `postgres_data` — сама база;
- `bot_data` — состояние диалогов (`/app/data`), чтобы кнопки продолжали
  работать после перезапуска бота.

## Веб-приложение (Telegram Mini App)

Приложение открывается прямо в Telegram: кнопкой «Заказ» слева от поля
ввода или «📱 Открыть приложение» в меню бота. Работает в одном процессе
с ботом и пользуется той же базой и теми же оповещениями.

Три вкладки внизу экрана:

| Вкладка | Что умеет |
|---|---|
| 📋 **Список** | Табак / Бар / Прочее со счётчиками, шкала заполненности с порогами, позиции по маркам и разделам (кто и когда добавил), поиск, «Копировать» — список текстом для поставщика. Администратору — «📤 Отправить Юре / Жене» |
| ➕ **Добавить** | Категория → марка или раздел → текст. Каждая строка — отдельная позиция, можно вставить сразу список |
| ✏️ **Правка** | ✏️ изменить текст или марку/раздел позиции, 🗑 удалить одну, «Выбрать» — удалить несколько разом, «Очистить» — заказ сделан (с оповещением команды). Администратору — список марок табака: добавить ✕ убрать |

Тема (светлая/тёмная) берётся из Telegram.

### Запуск

1. Нужен домен, указывающий на сервер (A-запись), и открытые порты 80/443.
2. В `.env`: `WEBAPP_DOMAIN=hookah.example.com` и
   `WEBAPP_URL=https://hookah.example.com/`.
3. `docker compose --profile https up -d --build` — Caddy сам выпустит
   сертификат и проксирует запросы в бота.
4. Перезапустите бота — он сам пропишет кнопку «Заказ» в меню чата.

Если на сервере уже есть nginx — не включайте профиль `https`, а
проксируйте свой домен на `127.0.0.1:8080`.

### Безопасность

Каждый запрос подписан Telegram (`initData`, HMAC от токена бота) —
сервер проверяет подпись и срок, поэтому подделать пользователя без
токена нельзя, а открыть приложение в обычном браузере — тоже. Права
те же, что в боте: добавлять, править и очищать может любой, кто
пользуется ботом; марки табака и «Отправить …» — только `ADMIN_IDS`.

## Как пользоваться

`/start` — регистрация и главное меню:

```
🌿 Табак   🍹 Бар   📦 Прочее      ← добавить позицию
📋 Список заказа
🗑 Очистить список
```

**Добавление** — сразу с главного меню:

| Категория | Шаги |
|---|---|
| 🌿 Табак | выбрать марку → написать название |
| 🍹 Бар | Напитки (Алко / Б-алко), Снеки или Чай → написать что закончилось |
| 📦 Прочее | написать что нужно |

**Просмотр и очистка** — в два шага: сперва кнопка действия, затем выбор
категории (Табак / Бар / Прочее) с возможностью вернуться назад.

**Счётчики.** На кнопке «📋 Список заказа» — сколько всего позиций ждёт
заказа, на кнопках выбора категории — сколько в каждой, в заголовке
списка — итог по категории и по каждой марке/подразделу. У пустых списков
счётчик не показывается. Считаются пункты, а не записи: многострочное
сообщение даёт столько позиций, сколько в нём непустых строк — ровно
столько, сколько пунктов видно в списке.

После любого завершённого действия меню приходит новым сообщением вниз —
листать за ним вверх не надо. Список при этом остаётся в чате отдельным
сообщением, а служебные («напишите ответным сообщением», выбор категории)
удаляются, чтобы не копился мусор.

При очистке списка всем остальным зарегистрированным пользователям
приходит оповещение, что заказ сделан.

**Заполненность.** У списков есть ёмкость — сколько позиций считается «100 %»:

| Пул | Ёмкость | Что входит |
|---|---|---|
| 🌿 Табак | 50 | все марки |
| 🍹 Напитки | 15 | Алко + Б/алко вместе |
| 📦 Прочее | 15 | всё |

Снеки и чай в заполненности не участвуют.

Оповещения приходят на трёх уровнях: 50 % — «🟡 заполнено наполовину»,
80 % — «🟠 скоро пора заказывать», 100 % — «🔴 пора делать заказ».

- **Кому:** ответственным за категорию (`RESPONSIBLE` в `.env`). Категорию без ответственного получают
  все зарегистрированные. Добавивший видит предупреждение прямо в ответе
  «✅ Добавлено» и в рассылку не попадает.
- **Каждый уровень объявляется один раз.** Бот помнит последний
  объявленный уровень по каждому списку; после очистки списка всё
  начинается заново.
- **Пропущенное догоняется.** Если список уже выше порога, а объявлено
  не было (например, порог добавили в настройки позже), оповещение уйдёт
  на ближайшем добавлении любой позиции.
- Если одно сообщение перескочило сразу несколько порогов, приходит
  только старшее оповещение.

**Ручная отправка.** Администраторам (`ADMIN_IDS`) в главном меню видны
кнопки «📤 Отправить Юре» и «📤 Отправить Жене» — по одной на каждого
ответственного. Кнопка **всегда** отправляет человеку его списки целиком
вместе с текущей заполненностью, независимо от порогов, и отвечает
отчётом: доставлено или нет и почему (например, «ещё не нажимал /start
в боте»). Длинный список делится на несколько сообщений.

> Ограничений доступа к спискам нет — добавлять и очищать может любой,
> кто знает бота. `ADMIN_IDS` управляет только кнопками «📤 Отправить …».

> Бот не может написать первым: чтобы получать оповещения, человек должен
> хотя бы раз нажать `/start`. Это ограничение Telegram.

## База данных

Таблица `registered_users`:

| Колонка | Тип | Описание |
|---|---|---|
| id | SERIAL | Первичный ключ |
| telegram_id | BIGINT UNIQUE | Telegram ID |
| username | TEXT | @username, если есть |
| full_name | TEXT | Имя пользователя |
| registered_at | TIMESTAMPTZ | Время регистрации |

Таблица `order_items`:

| Колонка | Тип | Описание |
|---|---|---|
| id | SERIAL | Первичный ключ |
| category | TEXT | tobacco / bar / other |
| subcategory | TEXT | Марка, Алко, Снеки и т.д. |
| content | TEXT | Что нужно заказать — одна позиция на запись |
| added_by | BIGINT | Telegram ID добавившего |
| added_at | TIMESTAMPTZ | Время добавления |
| is_done | BOOLEAN | Зарезервировано; очистка сейчас удаляет строки физически |

Многострочное сообщение сохраняется как несколько записей — по одной на
строку, чтобы каждую можно было править отдельно. Старые многострочные
записи разбиваются автоматически при запуске.

Таблица `tobacco_brands` — марки табака для кнопок бота и приложения.
При первом запуске заполняется из `TOBACCO_BRANDS` в `config.py`, дальше
редактируется в приложении.

| Колонка | Тип | Описание |
|---|---|---|
| id | SERIAL | Первичный ключ (он же в `callback_data` кнопок) |
| name | TEXT UNIQUE | Название марки |
| position | INTEGER | Порядок в списке |
